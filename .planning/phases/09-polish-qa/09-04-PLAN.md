1. In `mobile/lib/main.dart`:
   - Add import for the generated localizations: `import 'package:flutter_gen/gen_l10n/app_localizations.dart';` (or the path shown by `flutter gen-l10n` output)
   - In the `MaterialApp.router(...)` constructor, add these two properties:
     ```dart
     localizationsDelegates: AppLocalizations.localizationsDelegates,
     supportedLocales: AppLocalizations.supportedLocales,
     ```
   - If the import path differs from the standard `package:flutter_gen/gen_l10n/app_localizations.dart`, check the generated output. Common alternatives:
     - `import 'package:flutter_gen/gen_l10n/app_localizations.dart';`
     - The path depends on the `output-localization-file` in l10n.yaml

2. Run the final comprehensive QA pass:
   - `flutter analyze --fatal-infos` — must exit 0
   - `flutter test test/` — all unit/widget tests must pass
   - `flutter test integration_test/` — all integration test stubs must pass (skipped = pass)

3. If `flutter test test/` fails due to the new `localizationsDelegates` in MaterialApp breaking widget tests that use `MaterialApp` without delegates, the fix is:
   - Widget tests that pump `MaterialApp(home: ...)` might need `localizationsDelegates: AppLocalizations.localizationsDelegates` added — but this is unlikely since tests typically create their own MaterialApp that does not go through main.dart.
   - If it IS an issue, do NOT modify all widget tests. Instead, ensure the delegates are a no-op for English (which they will be since English is the template locale).

IMPORTANT: Do NOT replace any hardcoded strings with AppLocalizations lookups in this task. That is explicitly deferred — scaffold only.
