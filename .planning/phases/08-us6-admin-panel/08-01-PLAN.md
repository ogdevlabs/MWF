1. Create `admin/app/api/mux-upload/route.ts`:
   - Import `Mux` from `@mux/mux-node`
   - Import `createSupabaseServerClient` from `@/lib/supabase/server`
   - Instantiate Mux client with `process.env.MUX_TOKEN_ID` and `process.env.MUX_TOKEN_SECRET`
   - Export async `POST` function:
     a. Call `createSupabaseServerClient()` and verify user with `getUser()` — return 401 if no user
     b. Call `mux.video.uploads.create({ cors_origin: process.env.NEXT_PUBLIC_APP_URL ?? '*', new_asset_settings: { playback_policies: ['public'] } })`
     c. Return `Response.json({ uploadId: upload.id, url: upload.url })`
   - This endpoint is called by the VideoUploader client component before upload begins

2. Create `supabase/migrations/005_program_assets_bucket.sql`:
   - Create storage bucket `program-assets` for thumbnails and GLB 3D files
   - Policy: service role can upload (INSERT) — no student upload
   - Policy: authenticated users can read (SELECT) — students need to view thumbnails
   - SQL pattern (match existing `feedback-photos` migration style):
     ```sql
     INSERT INTO storage.buckets (id, name, public)
     VALUES ('program-assets', 'program-assets', false);

     -- Coach (service role) can upload
     CREATE POLICY "Service role can upload program assets"
     ON storage.objects FOR INSERT
     TO service_role
     WITH CHECK (bucket_id = 'program-assets');

     -- Authenticated users can read (thumbnails visible to students)
     CREATE POLICY "Authenticated users can read program assets"
     ON storage.objects FOR SELECT
     TO authenticated
     USING (bucket_id = 'program-assets');

     -- Service role can update/delete
     CREATE POLICY "Service role can manage program assets"
     ON storage.objects FOR ALL
     TO service_role
     USING (bucket_id = 'program-assets');
     ```
