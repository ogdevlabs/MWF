import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

/// App router with auth guard skeleton.
/// Routes are placeholders — real screens will be added in Phase 2+.
///
/// Auth guard logic:
/// - Unauthenticated users are redirected to /login
/// - Authenticated users who haven't seen onboarding go to /onboarding
/// - All other authenticated users go to /programs (home)
GoRouter createAppRouter({required bool isAuthenticated}) {
  return GoRouter(
    initialLocation: '/programs',
    redirect: (BuildContext context, GoRouterState state) {
      final loggingIn = state.matchedLocation == '/login';
      final signingUp = state.matchedLocation == '/signup';

      if (!isAuthenticated) {
        // Allow access to login and signup without auth
        if (loggingIn || signingUp) return null;
        return '/login';
      }

      // Authenticated user trying to access login/signup -> redirect to home
      if (loggingIn || signingUp) return '/programs';

      return null; // Allow navigation
    },
    routes: [
      GoRoute(
        path: '/login',
        name: 'login',
        builder: (context, state) => const _PlaceholderScreen(title: 'Login'),
      ),
      GoRoute(
        path: '/signup',
        name: 'signup',
        builder: (context, state) => const _PlaceholderScreen(title: 'Sign Up'),
      ),
      GoRoute(
        path: '/onboarding',
        name: 'onboarding',
        builder: (context, state) =>
            const _PlaceholderScreen(title: 'Onboarding'),
      ),
      GoRoute(
        path: '/programs',
        name: 'programs',
        builder: (context, state) =>
            const _PlaceholderScreen(title: 'Programs'),
        routes: [
          GoRoute(
            path: ':programId',
            name: 'program-detail',
            builder: (context, state) =>
                const _PlaceholderScreen(title: 'Program Detail'),
            routes: [

                    const _PlaceholderScreen(title: 'Session Player'),

}

# External Service Setup

This document lists the manual configuration steps that must be completed
outside of code before certain features will function. These steps require
human interaction with external dashboards and cannot be automated.

---

## 1. Firebase (Push Notifications)

**Required for:** Phase 7 — Coach Feedback push notifications

### Steps:

1. Go to [Firebase Console](https://console.firebase.google.com)
2. Create a new project named `mwf-pilates` (or your preferred name)
3. Add an iOS app:
   - Bundle ID: `com.fererelabs.mwfMobile`
   - Download `GoogleService-Info.plist`
   - Place in `mobile/ios/Runner/GoogleService-Info.plist`
4. Add an Android app:
   - Package name: `com.fererelabs.mwf_mobile`
   - Download `google-services.json`
   - Place in `mobile/android/app/google-services.json`
5. Install FlutterFire CLI and regenerate options:
   ```bash
   dart pub global activate flutterfire_cli
   firebase login
   flutterfire configure --project=YOUR_PROJECT_ID
   ```
   This replaces `mobile/lib/firebase_options.dart` with real values.
6. Enable Cloud Messaging in Firebase Console:
   - Project Settings -> Cloud Messaging -> Enable

### Environment Variables:

None required in `.env` — Firebase config is embedded in the generated files.

---

## 2. RevenueCat (In-App Purchases)

**Required for:** Phase 3 — Subscription gating

### Steps:

1. Create account at [RevenueCat Dashboard](https://app.revenuecat.com)
2. Create a new project named `MWF Pilates`
3. Configure platforms:
   - **Apple App Store:**
     - Add App Store Connect API key (Issuer ID, Key ID, .p8 file)
     - Set Shared Secret from App Store Connect
   - **Google Play Store:**
     - Add service account JSON credentials
     - Set up real-time developer notifications (RTDN)
4. Create Entitlements:
   - Create entitlement: `premium_access` (grants access to all programs)
5. Create Products:
   - Monthly: product ID `mwf_monthly_premium`
   - Annual: product ID `mwf_annual_premium`
6. Create Offerings:
   - Default offering with both monthly and annual packages
7. Configure Webhook:
   - URL: `https://YOUR_SUPABASE_PROJECT.supabase.co/functions/v1/revenuecat-webhook`
   - Authorization: Set the webhook secret
   - Events: `INITIAL_PURCHASE`, `RENEWAL`, `CANCELLATION`, `EXPIRATION`
8. Note API keys for the app:
   - Apple API Key → `REVENUECAT_APPLE_API_KEY`
   - Google API Key → `REVENUECAT_GOOGLE_API_KEY`

### Environment Variables:

| Variable | Where Used | How to Set |
|----------|-----------|------------|
| `REVENUECAT_APPLE_API_KEY` | Flutter app (--dart-define) | RevenueCat Dashboard -> API Keys |
| `REVENUECAT_GOOGLE_API_KEY` | Flutter app (--dart-define) | RevenueCat Dashboard -> API Keys |
| `REVENUECAT_WEBHOOK_SECRET` | Supabase Edge Function | `npx supabase secrets set REVENUECAT_WEBHOOK_SECRET=xxx` |

---

## 3. Mux (Video Hosting)

**Required for:** Phase 8 — Admin panel video uploads

### Steps:

1. Create account at [Mux Dashboard](https://dashboard.mux.com)
2. Create a new environment (or use default)
3. Generate API Access Token:
   - Settings -> API Access Tokens -> Generate new token
   - Permissions: Mux Video (Full Access)
   - Note Token ID and Token Secret
4. Configure Webhook:
   - Settings -> Webhooks -> Create endpoint
   - URL: `https://YOUR_SUPABASE_PROJECT.supabase.co/functions/v1/mux-webhook`
   - Events: `video.asset.ready`, `video.asset.errored`
   - Note the Signing Secret

### Environment Variables:

| Variable | Where Used | How to Set |
|----------|-----------|------------|
| `MUX_TOKEN_ID` | Admin panel (.env.local) | Mux Dashboard -> API Access Tokens |
| `MUX_TOKEN_SECRET` | Admin panel (.env.local) | Mux Dashboard -> API Access Tokens |
| `MUX_WEBHOOK_SIGNING_SECRET` | Supabase Edge Function | `npx supabase secrets set MUX_WEBHOOK_SIGNING_SECRET=xxx` |

---

## 4. Supabase (Backend)

**Required for:** All phases (auth, database, storage, realtime)

### Steps:

1. Go to [Supabase Dashboard](https://supabase.com/dashboard)
2. Create a new project:
   - Name: `mwf-pilates`
   - Region: Choose closest to target users
   - Note the generated password (for direct DB access)
3. After project is created, note:
   - Project URL (Settings -> API -> Project URL)
   - Anon Key (Settings -> API -> anon public)
   - Service Role Key (Settings -> API -> service_role secret)
4. Run the initial migration:
   ```bash
   npx supabase link --project-ref YOUR_PROJECT_REF
   npx supabase db push
   ```
5. Create Storage buckets:
   - `exercise-models` (for GLB 3D assets) — public read
   - `feedback-photos` (for student feedback images) — authenticated read
   - `program-thumbnails` (for program cover images) — public read

### Environment Variables:

| Variable | Where Used | How to Set |
|----------|-----------|------------|
| `SUPABASE_URL` | Flutter app (--dart-define) | Dashboard -> Settings -> API |
| `SUPABASE_ANON_KEY` | Flutter app (--dart-define) | Dashboard -> Settings -> API |
| `NEXT_PUBLIC_SUPABASE_URL` | Admin panel (.env.local) | Dashboard -> Settings -> API |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Admin panel (.env.local) | Dashboard -> Settings -> API |
| `SUPABASE_SERVICE_ROLE_KEY` | Admin panel (.env.local) | Dashboard -> Settings -> API |
