**sync_queue_table.dart** (T023) — CRITICAL: use `tableName_` getter with `.named('table_name')`:
```dart
import 'package:drift/drift.dart';

class SyncQueue extends Table {
  @override
  String get tableName => 'sync_queue';

  IntColumn get id => integer().autoIncrement()();
  TextColumn get operation => text()();
  TextColumn get targetTable => text().named('table_name')();
  TextColumn get payload => text()();
  IntColumn get createdAt => integer()();
  IntColumn get retryCount => integer().withDefault(const Constant(0))();
  TextColumn get lastError => text().nullable()();
}
```

Note: `autoIncrement()` automatically sets this column as PK — do NOT override `primaryKey` getter.
The column getter is named `targetTable` (not `tableName_` to avoid potential confusion) and uses `.named('table_name')` to set the actual SQL column name. This avoids the Drift getter conflict where a column named `tableName` would clash with the `Table.tableName` getter.

Create directory `mobile/lib/core/network/` and file `supabase_client.dart`.

This provider uses `@Riverpod(keepAlive: true)` because the Supabase client is a singleton that must persist for the app's lifetime. It accesses `Supabase.instance.client` which is initialized in `main()` before `runApp()`.

```dart
import 'package:riverpod_annotation/riverpod_annotation.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

part 'supabase_client.g.dart';

/// Provides the initialized [SupabaseClient] singleton.
///
/// Requires [Supabase.initialize] to have been called in main() before
/// the app starts. Uses keepAlive because the client must persist for
/// the entire app lifecycle — autoDispose would close connections mid-operation.
@Riverpod(keepAlive: true)
SupabaseClient supabaseClient(Ref ref) {
  return Supabase.instance.client;
}
```
